# 지율이의 신나는 하루

5세 아동과 부모가 함께 관찰하고 이야기하는 모바일 2D 놀이 게임입니다. 지율이, 하얀 몸과 갈색 귀를 가진 말티푸 지니, 친구 우리와 집·유치원의 이야기를 탐험합니다. 실제 사진·개인정보를 사용하지 않으며 발달을 평가하거나 치료 효과를 보장하지 않습니다.

## 놀이 화면 개편

그림 지도에서 장소를 고르면 **지율이가 걸어간 뒤 집 또는 유치원으로 들어갑니다.** Phaser 안에서 당근 인형을 옮기고, 지니가 물고 돌아오면 지율이가 받아 상자에 정리하며, 밥·물·휴식을 자유롭게 제공할 수 있습니다. 집 오른쪽 아래 책 그림으로 기존 집 이야기 2개에 들어가며, 유치원에서는 가위바위보와 무지개 블록만 고를 수 있습니다. 예전 유치원 시나리오 데이터와 저장 기록은 삭제하지 않습니다.

구현 범위·변경 파일·에셋·검증·재배포는 [자유놀이 리뉴얼](docs/자유놀이-리뉴얼.md), 음성 파일 제작은 [음성 제작](docs/음성-제작.md)을 참고하세요. 이전 [1.1 화면 개편 기록](docs/놀이화면-개편.md)도 보존합니다.

## 실행

Node.js 24와 npm을 사용합니다. 프로젝트 폴더에서 실행하세요.

```bash
npm ci
npm run dev
```

터미널의 주소를 Chrome에서 엽니다. 같은 와이파이에 있는 Android 기기에서는 컴퓨터의 로컬 IP와 포트로 접속할 수 있습니다. 개발 서버에서는 서비스 워커가 등록되지 않습니다. 홈 화면 설치와 오프라인 검증은 HTTPS 배포 주소 또는 컴퓨터의 localhost에서 수행하세요.

```bash
npm test
npm run build
npm run preview
```

브라우저 테스트는 실제 빌드 결과를 대상으로 합니다.

```bash
npx playwright install chromium
npm run test:e2e
```

기존 Chromium을 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 환경 변수에 실행 파일의 절대 경로를 지정합니다. 테스트 도중 서버가 자동으로 시작되고 종료됩니다.

## 집 자유놀이

지도에서 우리 집으로 들어가 당근 인형을 끌어놓으세요. 인형 → 바닥을 차례로 눌러도 됩니다. 지니가 물고 오면 지율이가 자동으로 받아 장난감 상자에 정리합니다. 정리를 마치면 지율이는 처음 자리로 돌아옵니다. 상자를 누르면 지율이가 앞으로 걸어가 당근을 꺼내 손에 듭니다. 던질 곳을 누르면 팔을 움직여 당근을 던지고, 포물선을 그리며 떨어진 인형을 지니가 물어옵니다. 큰 하얀 구름 말풍선 속 그림은 지니가 지금 원하는 것을 보여 줍니다. 사료 봉지나 물병을 누르면 지율이가 직접 들고 그릇에 부어 줍니다. 지니가 먹는 동안 용기를 제자리에 놓고 처음 자리로 돌아옵니다. 그릇으로 끌어놓거나 그릇을 눌러도 같은 동작으로 이어집니다. 침대를 누르면 쉬게 할 수 있습니다. 놀이가 쌓이면 갈증·배고픔·피로가 늘어나 당근 놀이만 반복해서 요구하지 않습니다. 빈 바닥을 누르면 지율이가 이동합니다. 정해진 완료 순서는 없습니다. 지니는 원하는 것을 말풍선으로 보여 주면서 방 안을 돌아다닙니다. 가끔 바닥에 배변하면 나타나는 **엄마!** 그림을 눌러 도움을 요청하세요. 엄마가 정리하고, 알맞은 행동에는 화면 중앙에 큰 초록 동그라미가 잠깐 나타납니다. 부모 설정을 열어 두거나 앱이 숨겨진 동안에는 배변 시간이 흐르지 않습니다.

## 유치원에서 우리와 놀기

우리가 지율이에게 다가와 “지율아, 같이 놀자!”라고 제안하면 아래 두 놀이 중 하나를 고릅니다.

- **가위바위보**: 아래 손 그림을 눌러 냅니다. 우리는 아이의 선택을 보기 전에 손을 정합니다. 먼저 3승하면 끝나고, 승패가 난 판은 최대 5판입니다. 비긴 판은 점수에 넣지 않습니다. 두 사람의 점수를 항상 표시합니다. 판이 끝나면 최소 3.8초 동안 결과를 보여 주고(음성이 길면 끝까지 기다린 뒤) 다음 판으로 자동 진행합니다. 3승한 뒤에는 결과 화면에서 새 놀이를 고릅니다.
- **무지개 블록**: 우리가 요청한 색을 고른 뒤 블록을 탑으로 끌어 놓거나, 탑 위의 놓을 위치를 누릅니다. **가운데에 올리기**도 지원합니다. 우리 차례에는 지율이가 색을 정해 줍니다. 빨강·주황·노랑·초록·파랑·남색·보라를 고루 요청합니다. 무게중심이 받침 범위를 벗어나면 탑이 넘어지며, 마지막 블록을 놓은 쪽이 패배합니다. 우리도 같은 균형 규칙을 따릅니다. 패배를 꾸짖지 않고 다시 함께 놀도록 제안합니다.

놀이 완료 기록은 기존 IndexedDB에 저장하며, 저장 구조를 삭제하거나 초기화하지 않습니다. 부모 설정과 화면 숨김 중에는 유치원 진행이 멈춥니다. 손 그림과 블록은 이 프로젝트에서 만든 SVG입니다. 대사는 `src/data/school.json`과 음성 manifest에 등록했습니다. **제목 1개와 우리 대사 14개에 생성형 AI 음성 파일을 적용했습니다.** 나머지 대사는 말풍선과 그림으로 표시합니다. 제목 음성은 앱을 열 때 한 번 자동 재생을 시도하며, 브라우저가 자동 재생을 막으면 제목 음성은 생략합니다. 장소를 선택할 때 뒤늦게 재생하지 않습니다. 제목을 눌러도 반복 재생하지 않습니다. 부모님 공간의 **새 목소리 들어보기**에서 샘플 네 개를 들어볼 수 있습니다.

## 기존 이야기 놀이 방법

집의 오른쪽 아래 책 그림으로 들어갑니다. 유치원의 이야기 놀이 진입 버튼은 제거했습니다. 다음 설정 중 선택지 수·관찰 시간·발화 확인은 기존 이야기용이며 자유놀이를 제한하지 않습니다.

1. 이야기 방 바닥에 있는 놀이 물건을 고릅니다.
2. 지니 또는 우리를 누릅니다. 기본 4초 동안 관찰할 수 있고 손가락 그림의 **놀자**로 바로 진행할 수도 있습니다.
3. 지니 돌보기는 선반의 사료·물병·목줄을 그릇 또는 문으로 옮깁니다. **물건을 누른 뒤 목적지를 누르는 방식**도 가능합니다.
4. 말풍선·친구·하트·쿠션 같은 그림은 눌러서 의사를 표현합니다. 블록 집은 바닥 블록 위로 옮길 수 있습니다.
5. 캐릭터의 움직임과 짧은 말풍선으로 반응합니다. 같은 행동도 친구의 상태에 따라 다른 결과로 이어집니다.
6. 마무리하면 같은 장면에서 **또 놀자 / 다른 놀이**로 이동합니다. 점수나 실패 화면은 없습니다.

오른쪽 위 톱니바퀴에서 부모 설정을 엽니다. 네 자리 숫자를 입력하면 선택지 개수(2/3/4), 대기 시간(0/4/8초), 음성 속도, 힌트·음성·발화 확인 버튼을 바꿀 수 있습니다. **전체 대사 자막**을 켜면 긴 대사를 항상 볼 수 있습니다. 기본 화면에서도 왼쪽 대사 버튼으로 원문을 펼칠 수 있습니다.

숫자 입력은 실수 방지용이며 보안 인증이 아닙니다. **말했어요**는 다음 선택 기록에 부모의 관찰을 함께 저장하며 정답 판정에 사용하지 않습니다. 부모 설정과 전체 대사 패널이 열린 동안 반응의 자동 진행은 멈춥니다.

## 구현 범위

| 이야기                 | 검증된 상황                                         |
| ---------------------- | --------------------------------------------------- |
| 지니가 배고파요        | 밥, 물, 산책                                        |
| 지니의 공이 없어졌어요 | 소파 아래, 상자 뒤, 옆방                            |
| 우리와 블록 놀이       | 함께 만들기, 다른 색, 다른 만들기 계획, 부족한 블록 |
| 우리가 속상해요        | 무너진 탑, 잃어버린 장난감, 놀이에서 짐, 혼자 쉬기  |

총 4개 에피소드, 14개 상황 변형입니다. 시나리오는 JSON이고 진행 코드는 분리되어 있습니다. React·TypeScript·Vite·Phaser 3·Tailwind CSS를 사용합니다. 그래픽은 직접 만든 SVG와 Phaser 도형입니다. 유료 에셋, 광고, 로그인, 결제, 서버, AI API, 분석 SDK가 없습니다.

## 패턴 암기 방지

- Fisher–Yates 셔플은 표시 순서만 바꾸며 행동 ID와 결과를 보존합니다.
- 선택지를 줄일 때는 적어도 하나의 마무리 행동을 포함합니다. 마무리 행동의 표시 위치는 실행 중 누적 횟수가 적은 위치를 우선해 편중을 완화합니다. 여러 적절한 행동을 하나의 정답으로 표시하지 않습니다.
- 상황은 검증된 조합에서만 선택합니다. 직전과 같은 변형은 피하고, 최근 3회에 없던 변형을 우선하는 확률(65%)과 익숙한 변형을 섞습니다. 선택 가능한 변형이 하나뿐이면 재사용합니다.
- 상황 방문 이력을 IndexedDB에 저장하므로 새로 열어도 연속 반복을 피합니다. 표현과 위치 균형의 세부 이력은 메모리에 유지합니다.
- 대화 표현은 상황별 행동의 `intent`에 연결합니다. 같은 도움 제안도 도움이 필요한 친구와 혼자 쉬고 싶은 친구에게 다른 결과를 만듭니다.
- 날짜, 에피소드·변형·행동 ID, 의도, 표시 순서, 선택지 표시 이후 응답 시간, 힌트·발화 관찰, 에피소드 방문 횟수, 마무리 여부와 조작 방식(누르기/끌어놓기)을 기록합니다.
- 부모 화면은 최근 선택의 같은 의도 횟수 같은 사실만 보여 줍니다. 빠른 반응이나 반복 선택을 암기·발달 수준으로 단정하지 않습니다.

## 새 에피소드 추가

`src/data/episodes.json` 배열에 기존 구조의 에피소드를 추가합니다. 집 이야기는 목록 UI에 자동으로 표시됩니다. 유치원은 현재 자유놀이 전용이며 기존 이야기 목록은 표시하지 않습니다.

1. 고유 `id`, 한국어 제목·설명, 장소 `place`, 인물 `character`를 지정합니다.
2. `variations`마다 고유 ID, 상태·물건·단서, 대사 배열, 힌트와 표정을 적습니다.
3. 각 상황에 최소 4개 행동을 정의합니다. 행동 ID는 해당 상황 안에서 고유해야 하며, `intent`, 그림 `icon`, 표현 `lines`, 결과 `result`, 표정 `mood`, 마무리 여부 `complete`가 필요합니다.
4. 모든 상황에 `complete: true` 행동을 하나 이상 넣습니다. 질문과 아직 해결되지 않은 반응은 `false`로 지정합니다.
5. 각 결과가 해당 장소·물건·친구의 의도와 일치하는지 사람이 검토하고 `npm test`를 실행합니다. 형식 검증만으로 대사의 의미를 완전히 검증할 수는 없습니다.

진행 엔진은 새 이야기 ID를 알 필요가 없습니다. 새로운 사물의 그림이나 장소를 도입할 때는 `GameScene`의 장면 표현을 추가합니다. `Place`에는 놀이터·게임방 식별자를 준비했지만 이번 MVP의 선택 화면에는 활성화하지 않았습니다. 지니가 유치원 학생처럼 등장하는 조합은 현재 검증 규칙에서 거부합니다.

## 캐릭터 교체

`art.ts`의 `characterSvg()`는 기본·기쁨·슬픔·생각·놀람과 눈 감은 상태의 이미지를 반환합니다. Phaser는 `인물-표정`, `인물-표정-blink` 키를 사용합니다.

PNG/WebP로 교체하려면 `GameScene.preload()`에서 같은 키에 `this.load.image()`를 사용하고, React의 처음·에피소드 화면 이미지도 같은 에셋 경로를 사용합니다. 240×300 비율과 투명 배경, 아래쪽 발 위치를 맞추면 기존 장면 좌표를 유지할 수 있습니다. 애니메이션 프레임을 늘릴 때는 스프라이트 시트 로더와 Phaser 애니메이션으로 바꿉니다.

## 음성·저장

`FileSpeechProvider`는 Manifest에 등록된 동일 출처 녹음 파일만 재생합니다. 브라우저 TTS와 실행 중 외부 API는 사용하지 않습니다. 파일 누락·재생 실패 시 그림과 자막으로 계속 진행합니다. **실제 고품질 녹음은 아직 0개**입니다. `npm run audio:catalog`로 모든 대사의 ID·경로·미생성 목록을 만들고 `npm run audio:import -- 대사ID 녹음파일경로`로 직접 녹음을 추가할 수 있습니다. 자세한 사용법은 [음성 제작](docs/음성-제작.md)을 참고하세요.

설정은 localStorage, 선택 기록과 상황 이력은 IndexedDB의 `jiyul-day` 데이터베이스에 저장합니다. 앱에서 외부 서버로 기록을 전송하지 않습니다. 사이트 데이터 삭제·브라우저 저장 공간 정리 시 기록이 없어질 수 있습니다. 저장이 거부되면 안내하고 메모리 상태로 놀이를 이어갑니다. 기록 내보내기 UI는 아직 없지만 `PlayRecord`와 저장 계층이 분리되어 있어 추가할 수 있습니다.

## Cloudflare Pages 배포

현재처럼 파일로 배포한 프로젝트는 새 ZIP을 내려받아 기존 프로젝트의 **Create a new deployment → Production**에 올리면 됩니다. [Cloudflare Direct Upload 안내](https://developers.cloudflare.com/pages/get-started/direct-upload/)와 [이번 버전 재배포 방법](docs/자유놀이-리뉴얼.md)을 참고하세요. 아래 Git 연결 방식은 새 자동 배포 프로젝트를 구성할 때의 별도 방법입니다.

GitHub에 이 폴더를 저장소 루트로 올린 뒤 Cloudflare Pages에서 해당 저장소를 연결합니다. Pages의 Git 연결은 커밋을 기반으로 자동 배포합니다. [Cloudflare Git 연결 안내](https://developers.cloudflare.com/pages/get-started/git-integration/)를 참고하세요.

| 항목                  | 값                                                                  |
| --------------------- | ------------------------------------------------------------------- |
| 프로젝트 루트         | 이 폴더를 저장소 루트로 올리면 비움. 상위 폴더를 올리면 `jiyul-day` |
| 빌드 명령             | `npm run build`                                                     |
| 출력 디렉터리         | `dist`                                                              |
| Node.js               | `24` (`.nvmrc`, 필요하면 환경 변수 `NODE_VERSION=24`)               |
| API 키·비밀 값·백엔드 | 필요 없음                                                           |

[React 배포 안내](https://developers.cloudflare.com/pages/framework-guides/deploy-a-react-site/)와 [빌드 설정](https://developers.cloudflare.com/pages/configuration/build-configuration/)을 함께 확인할 수 있습니다. `.github/workflows/check.yml`은 루트 저장소 기준 테스트·빌드·브라우저 검증을 실행합니다. 상위 폴더를 저장소 루트로 삼으면 워크플로 위치와 작업 디렉터리를 조정해야 합니다.

실제 계정 연결이나 공개 배포는 이 작업에서 수행하지 않았습니다. `dist`를 Pages Direct Upload로 올려도 실행할 수 있지만, 이후 Git 자동 배포를 원한다면 처음부터 Git 연결 프로젝트를 사용하는 편이 단순합니다.

## PWA와 업데이트

- 최초 온라인 방문에서 설치 캐시가 완료된 뒤 오프라인 재실행을 지원합니다. Android Chrome 메뉴에서 홈 화면에 설치할 수 있습니다.
- 빌드 파일 내용의 해시로 캐시 이름을 생성하므로 내용이 바뀌면 새 서비스 워커를 받습니다.
- 첫 설치로는 화면을 새로고침하지 않습니다. 새 버전은 대기 상태에 두고 놀이 화면을 벗어났을 때 업데이트 버튼을 보여 줍니다.
- 버튼을 누르면 새 워커가 활성화되어 화면을 다시 열고 이전 앱 캐시를 정리합니다. IndexedDB와 설정은 유지합니다.
- 기기 저장 공간이 부족하거나 캐시가 삭제된 경우 다시 온라인 방문이 필요합니다.
- 서비스 워커는 HTTPS 또는 localhost에서 동작합니다. [서비스 워커 수명주기 안내](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)를 참고하세요.

## 아직 포함하지 않은 기능과 다음 단계

이번 범위 밖인 놀이터·게임방 플레이, 음성인식, 사전 녹음 음원, 기록 내보내기 UI, 이동 조이스틱·충돌 물리는 구현하지 않았습니다. 실제 Android 기기의 녹음 재생·설치 UX·터치 느낌과 아이·부모의 놀이 관찰은 후속 확인이 필요합니다.

다음 개선은 실제 가족 플레이 피드백, 녹음 음성과 표현 애니메이션 보강, 검증된 상황 확장 순서를 권합니다. Phaser 엔진 청크는 크기 경고가 있지만 장면 진입 시 지연 로딩하고 이후 오프라인 캐시에 재사용합니다.
