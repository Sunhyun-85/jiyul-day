# 검증 기록

2026-10-20에 Node.js 24, Linux Chromium으로 검증했습니다. 실제 Android 기기를 원격으로 연결한 검증은 아닙니다.

## 자동 검증

최종 실행에서 Vitest 21개와 Chromium 브라우저 테스트 9개가 모두 통과했고, `npm run build`도 성공했습니다. 서비스 워커 업데이트 테스트는 브라우저의 갱신 지연을 포함해 약 1분이 걸렸습니다. 실행 명령은 `npm test`, `npm run build`, `npm run test:e2e`입니다.

- Vitest: 선택 위치 분산, 재현 가능한 시드, 상황 반복 방지·안전한 재사용, 표현 교대, 축소 선택지의 완료 경로, 14개 상황의 전체 행동 연결, 복수 적절 행동, 거절 후 대화, 잘못된 자료 거부, 설정·IndexedDB 유지, 음성 실패 처리.
- Chromium: 360×800, 800×1100, 900×500 놀이 화면의 가로·세로 넘침 없음, 보이는 버튼의 최소 44×44 CSS px, 실제 장면의 픽셀 렌더링, 4개 에피소드 완료와 복귀, 음성 불가 환경의 진행, 부모 설정·기록 유지, 관찰 시간과 건너뛰기, 즉시 설정 반영, 오프라인 재실행, 놀이를 벗어난 뒤 새 버전 적용과 설정 유지.
- TypeScript 검사와 Vite 프로덕션 빌드, 콘텐츠 해시 기반 서비스 워커 생성.
- 설치 시 npm 의존성 감사에서 취약점 0건 확인.

브라우저 테스트는 `pageerror`도 수집합니다. 캔버스 요소가 존재하는지만 검사하지 않고 실제 그림 픽셀을 확인합니다. 생성한 모바일·태블릿 스크린샷을 직접 확인했습니다.

## 1.1.0 놀이 화면 개편 검증

- 짧은 말풍선과 결과 문구 길이, 물건별 목표 지정과 놓기 판정의 경계값을 검사했습니다.
- 잘못된 곳에 끌어놓으면 기록 없이 돌아오고, 올바른 곳에 놓으면 `drag` 기록과 반응이 생기는지 확인했습니다.
- 밥·물·산책의 서로 다른 요구, 두 번 눌러 물건 사용하기, 산책 시 보호자 등장, 네 이야기의 완료 경로를 확인했습니다.
- 친구가 도움을 거절한 뒤 기다려 주기, 부모 창을 연 동안 자동 진행 정지, 자막 설정 유지도 확인했습니다.
- 모바일·태블릿·가로 화면의 지도와 놀이 스크린샷을 확인했습니다.

## 발견하고 수정한 결함

1. Phaser SVG 로더가 URI 인코딩 데이터를 Base64로 해석해 빈 장면이 되던 문제: UTF-8 Base64 SVG 주소로 통일했습니다.
2. 첫 서비스 워커 설치 시 놀이가 새로고침되던 문제: 첫 제어권 획득과 후속 업데이트를 구분했습니다.
3. 미리보기 서버의 `Vary` 헤더로 오프라인 정적 파일을 놓치던 문제: 동일 출처의 버전 고정 캐시에서 헤더 차이를 무시하고 조회합니다.
4. 한국어 음성·음성 중지 API가 제공되지 않는 환경: 실패 값을 반환하고 그림·텍스트로 계속 진행합니다.
5. 화면 크기를 바꾸는 동안 진행 중이던 캐릭터 동작이 예전 좌표로 돌아가던 문제: 크기 재계산 전에 기존 동작을 중지합니다.
6. HTTP 로컬 와이파이 환경에서 UUID API가 없는 경우: 보안 인증과 무관한 기록 ID에 로컬 대체 생성기를 사용합니다.

## 검증 한계

실제 Android 스마트폰·태블릿에서의 기기 음성, 브라우저 설치 메뉴, 장시간 사용, 아동·부모의 실제 놀이 반응은 후속 확인이 필요합니다. 게임 기록으로 발달 수준을 추론하지 않습니다. 놀이 화면은 스크롤 없이 사용하며, 부모 설정과 전체 대사 영역은 필요한 경우 내부 스크롤을 허용합니다. 실제 기기의 주소 표시줄과 화면 회전에 따른 높이 변화는 추가 확인이 필요합니다.

Phaser 엔진 청크는 약 1.20 MB(전송 압축 약 319 KB)로 크기 경고가 있습니다. 실행 오류는 아니며 장면 진입 시 지연 로딩하고 서비스 워커에 저장합니다. 네트워크가 느린 실제 기기에서 첫 설치 시간을 추가 확인할 수 있습니다.
