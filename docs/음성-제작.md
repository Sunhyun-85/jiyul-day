# 파일 음성 제작

실행 중에는 같은 사이트에 포함된 파일만 재생합니다. SpeechSynthesis, 외부 AI 요청, 프런트엔드 API 키를 사용하지 않습니다. 현재 139개 고유 대사/효과음 항목 중 Gemini로 만든 실제 WAV 파일 27개가 포함되어 있습니다. 제목 1개와 우리 대사 26개이며, 나머지 112개(사람 대사 109개, 강아지 효과음 3개)는 아직 없습니다. 추가 생성 중 API가 HTTP 429를 반환하여 자동 재시도 없이 중단했습니다. 이는 재생 시스템 구현과 음성 콘텐츠 제작을 구분한 상태입니다.

## 대사 추출

```bash
npm run audio:catalog
```

`src/data/episodes.json`, `src/data/home.json`, `src/data/school.json`에서 추출하여 다음 파일을 만듭니다.

- `public/audio/manifest.json`: `dialogue_id`, `character_id`, `text`, `audio_path`, `emotion`, `available`.
- `public/audio/missing.json`: 미생성 목록.
- `src/data/audio-manifest.json`: 앱에 포함하는 동일한 Manifest. 빌드 때 자동 재생성.

화자와 NFC 정규화한 문장의 SHA-256 일부로 ID를 만듭니다. 다른 문장으로 수정하면 ID도 달라져 예전 녹음을 잘못 재생하지 않습니다. 같은 문장은 같은 파일을 재사용합니다. 지니 관련 설명은 내레이터가 말합니다. `jini` 항목은 멍·낑낑·하품용 녹음이며 사람 TTS로 생성하면 안 됩니다.

## 직접 녹음 추가

`missing.json`에서 대사와 ID를 확인하고 녹음합니다. MP3, PCM WAV, OGG를 사용할 수 있습니다.

```bash
npm run audio:import -- narrator_실제ID /절대/경로/녹음.mp3
npm run build
```

녹음 파일은 `public/audio/narrator/ID.mp3`, `hauri/ID.mp3`, `jini/ID.mp3` 등으로 복사됩니다. 자동으로 존재 여부와 형식을 검사하고 Manifest를 갱신합니다. 직접 같은 경로에 복사한 뒤 `audio:catalog`를 실행해도 됩니다. `effects` 폴더는 향후 녹음 효과음용입니다. 테스트용 합성 WAV는 테스트 실행 중만 제공하며 배포 음성에 포함하지 않습니다.

`npm run audio:validate`는 누락 음성도 실패로 처리하는 엄격한 검사입니다. 현재는 미녹음 상태이므로 이 명령이 실패하는 것이 정상이며, 일반 빌드는 누락을 허용합니다. 잘못된 형식의 기존 파일은 일반 빌드도 실패합니다. 기본 검사는 파일 헤더 기반이고, 로컬에 `ffprobe`가 설치되어 있으면 디코더 검사를 추가합니다. Manifest의 `validation`에 실제 수행 수준을 기록합니다. 재생 가능 여부와 발음·억양 품질은 녹음자가 직접 들어 확인해야 합니다.

## 향후 생성 서비스 연결

`scripts/audio/voice-profiles.json`은 화자별 지침과 선택할 서비스/목소리 ID의 자리입니다. 내레이터는 따뜻한 성인, 우리는 과장되지 않은 어린 친구 느낌, 지율이 직접 음성은 최소화합니다.

어댑터 계약은 `render(dialogue, {voiceProfile, outputPath}) => Promise<void>`입니다. 구현된 입력 경로는 **직접 녹음 가져오기**입니다. ElevenLabs, Google Cloud TTS, Azure Speech의 실제 네트워크 어댑터와 자동 생성 호출은 아직 구현·실행하지 않았습니다. 사용자가 서비스를 선택하고 비용을 승인한 뒤 CLI 전용 어댑터를 추가하면 동일 Manifest를 사용할 수 있습니다. 환경변수 키를 빌드 산출물이나 `VITE_*`에 넣지 않습니다.

자연스러운 목소리 제작이 끝났다고 보고할 수 있는 시점은 실제 녹음을 넣고 발음·억양·화자 일관성까지 들어 확인한 뒤입니다.

## Gemini 샘플 제작 및 확인

`node --env-file=.env.audio.local scripts/audio/gemini-samples.mjs`는 요청 계획만 표시합니다. 실제 생성에는 `--generate`가 필요하며, `--title`을 추가하면 제목 한 개만 대상으로 합니다. 기존 파일은 건너뛰고 오류는 자동 재시도하지 않습니다. API 키 파일과 검토 전 `audio-previews/`는 Git에서 제외됩니다. 모델은 `gemini-3.8-flash-tts`, 제목 목소리는 `Puck`, 우리 목소리는 `Leda`에 가상의 다섯 살 남자아이 연기 지시를 적용했습니다. 기존 성인 남성 느낌의 우리 샘플을 교체했습니다. 생성 결과의 발음과 연령 느낌은 사용자 청취로 검토해야 합니다.

게임을 새로 열면 제목 음성을 한 번 자동 재생합니다(게임 음성 설정이 켜져 있어야 합니다). 브라우저가 자동 재생을 거절하면 제목 음성은 생략합니다. 장소 선택이나 제목 터치로 나중에 재생하지 않습니다. 제목 클릭 기능은 없으며 지도로 돌아와도 반복하지 않습니다. 유치원에서는 초대와 일부 색상 요청·힌트, 가위바위보 결과 등에 파일이 연결됩니다. 부모님 공간의 **새 목소리 들어보기**에서는 네 파일을 원래 속도로 직접 재생할 수 있습니다. 이 미리 듣기는 게임 음소거 설정과 별도로 직접 조작합니다.

## 나머지 음성 생성

```bash
npm run audio:catalog
node scripts/audio/gemini-samples.mjs --missing
node --env-file=.env.audio.local scripts/audio/gemini-samples.mjs --missing --generate
npm run audio:catalog
```

`--missing`은 등록된 미생성 사람 대사를 대상으로 합니다. 현재 집·유치원 대사를 우선하고 보존된 기존 시나리오를 이어서 생성합니다. 지니의 짖음·하품은 사람 목소리로 생성하지 않습니다. 기존 WAV는 덮어쓰지 않으며 요청 사이에 21초를 기다립니다. HTTP 오류(무료 할당량 초과 포함)가 발생하면 즉시 중단하고 자동 재시도하지 않습니다. 성공한 파일은 `public/audio`에 남으며 카탈로그 재생성 후 게임에서 재생됩니다. 실행 전에 사용자 승인과 프로젝트의 요금제·할당량을 확인해야 합니다. 이 옵션 자체가 무료 여부를 보장하지는 않습니다.

우리 대사는 사용자가 선택한 Leda + 어린 남자아이 연기 설정을 유지합니다. 내레이터는 Puck을 사용합니다. 생성 메타데이터는 Git에서 제외한 `audio-previews`에 남습니다.

2026-10-23 재개: 우리 대사 2개를 추가했습니다. 세 번째 요청에서 HTTP 429가 반환되어 중단했습니다. 응답 코드만으로 일일 한도와 분당 제한을 구분할 수 없어 복원 시각을 단정하지 않습니다.

추가 소량 확인에서는 3개 요청이 모두 성공하여 총 20개 음성이 준비됐습니다. `--missing --limit=3 --generate`로 생성 개수를 제한할 수 있습니다. 오류가 발생하면 민감한 응답 원문 대신 제한 항목 ID와 재시도 지연(제공된 경우)만 표시하고 중단합니다.

계속 생성한 작업에서 우리 대사 7개를 추가해 총 27개(유치원 26/33개)가 준비됐습니다. 다음 요청의 HTTP 429 응답에는 제한 항목과 재시도 시간이 없어 추가 요청을 중단했습니다. 집 내레이터를 포함한 사람 대사 109개와 강아지 효과음 3개는 미생성입니다.
